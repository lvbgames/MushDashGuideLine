# Internal Privacy Request Runbook

내부 운영 전용. 이 문서는 공개 사이트에 노출하거나 이용자에게 원문 그대로 전달하지 않는다. 비밀번호, 인증 토큰, client secret, 암호화 material, 전체 신분증 사본 또는 실제 UserCloud payload를 이 문서와 일반 작업 기록에 남기지 않는다.

기준일: 2026-07-31. 공개 Privacy의 `Last updated`와 별개이며, 법률 자문을 대체하지 않는다.

## 1. 적용 범위와 현재 한계

- 접수 채널: `lvb909@naver.com`
- 담당부서: Lv.B
- 요청 유형: 열람, 정정, 삭제, 처리정지와 개인정보 관련 문의
- 대상: 홈페이지 이메일 기록, Mush Dash EOS UserCloud, Lv.B가 직접 관리하는 기타 확인 가능한 기록
- 현재 Mush Dash에는 이용자가 직접 실행하는 UserCloud 삭제 UI와 프로젝트 소스의 cloud-file delete 호출이 없다.
- 현재 저장소에는 이메일 발신자가 특정 Steam/Epic/EOS 계정의 소유자임을 확정하는 운영 도구나 검증된 절차가 없다. 표시 이름만으로 본인 확인을 완료하지 않는다.
- EOS/온라인 서비스에는 이용자 파일 삭제 기능이 존재하지만, 현재 Mush Dash가 그 기능을 호출하지는 않는다. Developer Portal 또는 지원 절차의 제품별 처리 가능 범위는 실제 운영 계정에서 별도 확인해야 한다.

## 2. 접수 기록

요청을 받으면 다음 최소 항목을 내부 요청 기록에 남긴다.

1. 접수일
2. 요청 유형: 열람 / 정정 / 삭제 / 처리정지 / 기타 문의
3. 게임 또는 서비스: Mush Dash / 홈페이지 이메일 / 기타
4. 플랫폼: Steam / Epic Games Store / 해당 없음 / 미확인
5. 요청 범위: UserCloud 게임 저장 / 이메일과 첨부 / 특정 정보 / 전체로 주장된 범위
6. 회신용 이메일 주소
7. 상태: 접수 / 본인 확인 대기 / 범위 확인 대기 / 플랫폼·EOS 확인 중 / 처리 중 / 완료 / 제한 또는 불가

실제 payload, 전체 계정 식별자, 비밀값과 불필요한 첨부는 요청 관리 문서에 복제하지 않는다.

## 3. 이용자에게 받을 최소 정보

- 요청하는 권리와 구체적인 범위
- 대상 게임 또는 서비스
- 이용 플랫폼
- 게임 화면에 보이는 표시 이름: 계정 탐색 보조 정보일 뿐 본인 확인 수단이 아님
- 회신 가능한 이메일 주소

다음은 요구하지 않는다.

- 비밀번호, 로그인 코드, 인증 토큰, 세션 정보, client secret
- 전체 신분증 사본 또는 신분증 번호
- 계정 설정 화면의 불필요한 전체 캡처
- 다른 게임이나 다른 이용자의 정보

플랫폼 또는 EOS의 승인된 지원 절차가 특정 식별자를 요구하는 경우에도 일반 이메일로 임의 수집하지 않는다. 해당 절차의 안전한 제출 경로, 필요 범위와 보관 방식을 먼저 확인한다.

## 4. 본인 및 대상 계정 확인

현재 구현만으로 확정된 본인 확인 절차는 없다. 다음 순서로 처리한다.

1. 게임, 플랫폼, 표시 이름과 요청 범위를 확인한다.
2. 표시 이름만 일치한다는 이유로 데이터 열람·정정·삭제를 실행하지 않는다.
3. 해당 플랫폼 또는 EOS 지원 절차에 계정 소유 확인과 제품별 UserCloud 처리 방법을 문의한다.
4. 승인된 플랫폼 내 확인, EOS 지원의 권한 확인 또는 향후 검증된 게임 내 확인 절차가 마련된 경우에만 계정과 요청자를 연결한다.
5. 안전한 연결을 확인할 수 없으면 데이터를 공개하거나 삭제하지 않고, 확인 불가 사유와 가능한 다음 단계를 이용자에게 알린다.

신원 확인 절차가 새로 확정되면 이 문서에 필요한 정보, 확인 주체, 성공 기준과 증거 보관 범위를 먼저 기록한 뒤 사용한다.

## 5. Mush Dash UserCloud 범위

현재 정상 게임 계약은 다음 여섯 범주다.

- 프로필: 튜토리얼 진행, 표시 이름, 아이콘·이름표·아바타 선택
- 재화 잔액
- 보유 꾸미기 항목과 인벤토리
- Infinity Tower 최고 기록
- 주간 도전 ID·진행·완료·보상 수령·주차
- 중복 구매 처리를 방지하기 위한 거래 식별자

내부 파일 계약과 코드 근거는 `PRIVACY_USERCLOUD_AUDIT.md`에서만 확인한다. development 검증 파일은 일반 이용자 gameplay 범주와 분리한다.

계정 식별자는 계정별 UserCloud 영역을 찾는 SDK 호출 인자이며, 감사한 정상 JSON payload의 필드는 아니다. 표시 이름은 프로필 payload에 저장된다.

## 6. 요청 유형별 처리

### 열람

- 먼저 요청자와 대상 계정의 안전한 연결을 확인한다.
- 연결 전에는 실제 UserCloud JSON이나 다른 계정 정보를 제공하지 않는다.
- 연결이 확인되더라도 제공 범위와 형식은 적용 법령, 플랫폼/EOS 절차와 제3자 정보 포함 여부를 검토한다.
- 기술적 열람 경로가 확인되지 않으면 공개 Privacy의 범주 설명, 현재 제한과 플랫폼/EOS 확인 상태를 회신한다. 이를 실제 데이터 열람 완료로 표현하지 않는다.

### 정정

- 게임 내에서 이용자가 직접 변경할 수 있는 표시 이름·선택 설정은 검증된 정상 게임 기능을 우선 안내한다.
- 원본 UserCloud JSON을 이메일로 받아 수동 편집하거나 검증 없이 덮어쓰지 않는다.
- 현재 기능으로 정정할 수 없는 항목은 계정 확인 후 플랫폼/EOS 지원 또는 별도 승인된 게임 수정이 필요한지 판단한다.

### 삭제

1. 요청자, 게임, 플랫폼과 삭제 범위를 확인한다.
2. 요청이 Mush Dash에만 한정되면 다른 게임, 다른 제품 또는 조직 전체 데이터를 삭제하지 않는다.
3. 현재 게임에는 cloud-file delete 호출이 없으므로 게임이 처리했다고 가정하지 않는다.
4. 제품별 UserCloud 파일을 삭제할 수 있는 플랫폼/EOS API·지원 절차와 담당 권한을 확인한다.
5. 제품 범위를 벗어날 수 있는 조직 단위 Developer Portal `Delete User`는 기본 절차로 사용하지 않는다. 계정 연결과 여러 게임·데이터에 미치는 범위를 운영자와 Epic 지원이 확인하고, 이용자가 그 범위를 명시적으로 요청한 경우에만 별도 승인 대상으로 검토한다.
6. 처리했다면 대상 범위, 파일별 성공·실패, 부분 실패와 재시도 결과를 확인한다. 재열거 또는 플랫폼/EOS의 권위 있는 완료 확인 전에는 삭제 완료라고 회신하지 않는다.
7. 기술적 또는 법적 제한이 있으면 사유, 현재 처리한 범위와 다음 단계를 회신한다.

게임 삭제나 계정 연동 해제만으로 UserCloud가 자동 삭제된다고 안내하지 않는다.

### 처리정지

- Lv.B가 보유한 이메일 문의 기록은 법적 보존·계약·분쟁 대응 필요 여부를 확인하고 불필요한 사용을 중단한다.
- 온라인 저장 기능에 필요한 UserCloud 처리를 정지하는 기술 경로는 현재 게임에 구현되어 있지 않다. 계정 확인 후 플랫폼/EOS 지원과 적용 법령을 검토하고, 가능한 조치와 기능 영향 또는 제한을 안내한다.

## 7. 이메일·첨부 파일 검색과 삭제

- 요청자의 회신 이메일, 접수일, 제목과 확인된 범위로 NAVER 메일함과 관련 보관 위치를 검색한다.
- 일반 문의 및 게임 지원 이메일과 첨부는 문의 처리 완료 후 1년 보관 정책을 적용한다.
- 계약·거래·분쟁 관련 기록은 관련 법령상 기간 또는 해당 관계가 종료될 때까지의 예외를 먼저 확인한다.
- 법적 보존 대상은 일반 문의 기록과 분리하고, 근거가 끝나면 삭제한다.
- 이메일 사업자 또는 발신자 측 기록처럼 Lv.B가 직접 관리하지 않는 정보는 해당 사업자의 절차를 안내한다.

## 8. 결과 통지

회신에는 다음을 포함한다.

- 접수한 요청 유형과 확인한 범위
- 완료한 조치와 완료 범위
- 처리하지 못했거나 제한된 항목과 사유
- 부분 실패가 있으면 대상과 재시도 또는 다음 단계
- 외부 플랫폼이 직접 관리하는 정보의 문의 경로

즉시 처리, 무조건 삭제 또는 모든 플랫폼 데이터 삭제를 보장하지 않는다. 법정 회신 기한은 적용 법령과 법률 검토로 확정하며 임의의 기간을 약속하지 않는다.

## 9. 최소 내부 처리 기록

다음만 보관한다.

- 접수일, 요청 유형, 게임·플랫폼·범위
- 본인 확인에 사용한 절차의 종류와 결과; 비밀값과 실제 식별자 원문은 제외
- 처리 결정, 처리일, 완료·제한·실패 범위
- 이용자에게 보낸 최종 회신일
- 법적 보존 예외가 있으면 근거 종류와 종료 검토일

개인정보 요청 처리 기록 자체의 보유기간은 아직 확정되지 않았다. 사용자가 법률 검토를 거쳐 기간과 삭제 담당자를 정하기 전에는 임의의 영구 보관 또는 자동 삭제 정책을 만들지 않는다.

## 10. 향후 게임 내 삭제 기능 권장 사양

별도 Mush Dash 작업으로 다음 기능을 구현·검증하는 것을 권장한다. 이번 홈페이지 작업에는 포함하지 않는다.

- 로그인된 이용자가 자신의 Mush Dash 정상 UserCloud 여섯 파일만 삭제
- 삭제 범위와 복구 불가 가능성을 알리는 명시적 확인 UI
- 삭제 직전·직후 원격 파일 목록 재열거
- 로컬 설정을 유지할지 초기화할지에 대한 명확한 제품 정책
- 파일별 부분 실패, 재시도와 최종 결과 표시
- Steam과 Epic Games Store 각각의 Development 계정 검증
- 다른 Lv.B 게임, 다른 EOS 제품과 계정 연결에 영향이 없음을 검증

## 11. 공개 Privacy와 Effective date 운영

- 공개 문구에는 일반 데이터 범주, 현재 삭제 기능의 한계와 요청 채널만 둔다. 내부 파일명, C++ field, SDK 함수명, development 검증 파일과 보안 finding을 노출하지 않는다.
- 공개 문서의 최종 수정일과 시행일은 사용자 승인 운영 배포일 `2026-08-03`으로 확정한다.
- 이후 정책 변경 시 네 언어에 같은 날짜와 의미를 반영하고 `npm run check`, `npm run build`, `prepare-production.ps1`, 네 route 의미 동등성 검사를 다시 수행한다.
